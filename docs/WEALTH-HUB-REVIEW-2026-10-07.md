# Wealth hub review, October 7, 2026

Work stayed on `wealth-hub`. The review started at `16b22cc`. Nothing was pushed, merged or deployed. The existing `.muserules` file was left alone. Changes target the hub, its tests and its entries in `llms.txt`. No Medicare page, style, route or shared chrome component was changed during this review. The branch already contained Medicare changes before this task; its full diff against `master` is therefore broader than this review's fixes.

**Mission 1: confirmed defects and fixes.** Saved calculator data now rejects damaged shapes and nonfinite numbers, keeps stable hydration snapshots and updates across browser tabs. Compound shared values preserve the supported $10 million maximum. Fractional years and age-limited waiting comparisons now match the calculation. Zero deposits no longer produce misleading growth copy. The Roth comparison states its equal pretax basis, full deduction assumption and qualified withdrawal assumption. Debt results distinguish the 50-year simulation limit from a payment that cannot reduce principal, and duplicate debt names remain distinct. Budget CSV rows reconcile to the entered income in cents. Decimal entry now accepts values such as 5.5 without turning them into 55.

Hand-worked checks cover a $1,000 debt at 12% APR with $600 monthly payments: $410 remains after month 1, the final payment is $414.10, and total interest is $14.10. A $601 balance at 0% with $1 monthly payments still has $1 left at month 600. The Roth check uses $1,000 pretax each year for 3 years at 10% growth, 10% tax now and 20% later. Its gross balance is $3,310; traditional net is $2,648 and Roth is $2,979, a $331 difference.

The signup endpoint rejects null, arrays, malformed JSON and streamed bodies above 4,096 bytes. Tests cover validation, the honeypot, bot verification, five attempts per ten minutes and delivery failure. Quizzes cancel pending transitions on Back and unmount, ignore duplicate rapid answers, scope number shortcuts, and move focus to the next question or result. Hostile shared values fall back safely. Newly generated calculator links put values in the URL fragment, which is not sent in HTTP requests. Legacy query links remain accepted for compatibility; opening an old query link still puts those old values in the request URL.

The existing rate limiter is process-local. Its behavior across production instances and restarts remains a deployment concern, not a verified global abuse limit. Real email delivery and live bot verification were not exercised. Browser checks blocked API submissions; unit tests used mocks. Consent text and the data collected about a person were not changed.

**Mission 2: browser use and motion.** Chrome checked all 23 hub pages at 360x740, 390x844, 430x932 and 1440 pixels wide: 92 page/viewport checks, with no remaining horizontal overflow or page exceptions. The original calculator panel pseudo-element caused a 2-pixel phone overflow. Giving the panel its proper positioning context fixed it. Phone navigation now wraps with 44-pixel targets, and the footer brand no longer breaks its final letter onto another line.

Browser interactions dragged every calculator input slider, exercised keyboard endpoints, removed all debts, added a debt and entered a decimal APR. Actual downloads produced the budget CSV, Excel workbook and ratio-checker ZIP. All 8 first-$1,000 outcome branches and shared plans worked. The personality quiz exercised every answer option through 4 complete runs and opened all 4 shared result pages. That covers each option and outcome, not every possible answer combination. Unit tests add tie and malformed-result coverage.

Motion was inspected in phone screenshots, timed sequences and a 4x CPU-throttled Chrome session. The hero slider no longer moves itself. The ticker is static; continuous panel effects and expensive blur are disabled on phones. Pointer-leave cancels pending motion updates. Reduced-motion mode suppresses transitions, reveals, number easing, chart drawing and confetti. All 23 pages remained readable with zero running animations in the final reduced-motion check. The four-second frame sample went from 191 to 225 frames, with a 95th-percentile interval of 33.4 ms before and 33.3 ms after. The after sample still had one 66.8 ms frame, so these results do not establish steady 60 fps.

All five Lighthouse accessibility scores were 100. Axe WCAG 2.0 A/AA and 2.1 AA checks found zero violations on all 23 pages. Keyboard checks covered calculator controls, chart endpoints and quiz progression. Charts now expose a labeled keyboard slider and readable series values, including a one-point chart. Automated contrast checks include the rendered lime, cobalt and coral combinations. These checks are not a WCAG certification. No native screen reader such as NVDA or VoiceOver was used; the browser accessibility tree and focus order were inspected instead.

**Mission 4: a focused exploration improvement.** Browser testing showed that a visitor could finish a tool and face the same general collection again. A single next-tool prompt now suggests a related tool they have not opened. It reuses the existing local `cbw:explored` list. It adds no tracking, new stored fields or network calls. Tests cover preferred related choices, unknown saved slugs, no history and all tools already opened. The [phone capture](wealth-review/next-tool-390.png) shows the prompt. Keeping someone exploring for 20 minutes remains a hypothesis; no retention study or live analytics experiment was run. This addition followed the correctness and accessibility fixes; the performance limitations above remain open.

**Mission 5: rendered search metadata and internal links.** All 23 pages were checked for a title, description, canonical, share image and parseable JSON-LD. The generic hub image and four personality images returned PNG responses. Hub article author and publisher data now identify Christian and link to his hub journey. Article images use the wealth image rather than a Medicare image. JSON-LD serialization escapes opening angle brackets. Every calculator and quiz page links to a related article, and every article links to a tool. The personality quiz's final related link now goes directly to the 50/30/20 article. Tests confirm the sitemap and `llms.txt` include every hub page; missing hub collection, journey and links entries were added to `llms.txt`.

Unsupported personal anecdotes and claims were removed. Content checks were strengthened rather than loosened. The 2026 IRA limit of $7,500, 401(k) limit of $24,500 and Roth income ranges were checked against the [IRS 2026 announcement](https://www.irs.gov/newsroom/401k-limit-increases-to-24500-for-2026-ira-limit-increases-to-7500). The Roth ranges are $153,000–$168,000 for single filers and $242,000–$252,000 for married couples filing jointly.

Local configuration produces localhost canonicals and preview noindex directives. Lighthouse SEO scored 66 on the four wealth pages and 69 on `/links`; these are preview results. Production-domain canonicals, indexing and search appearance remain unverified. The root layout also emits inherited site/insurance structured data on hub pages. Hub-specific schema is corrected, but complete schema separation requires a root-layout change outside the current allowed scope. JSON parsing and schema field checks were performed; no external rich-results certification was obtained.
